# 第63回熊工定演 ゲネプロ無料見学受付システム（構築用）

対象：2027年1月16日（土）9:45受付、10:00〜11:30見学、11:30〜11:45順次解散。
未成年者と保護者の個人情報を扱うため、**本番公開前に校内承認・担当者による実機試験が必須**です。

## ファイル

- `index.html`：GitHub Pages用。保護者のメール入力および申込フォーム。
- `Code.gs`：Google Apps Script。メール認証、受付台帳保存、QRメール配信。

## 手順

1. 学校管理のGoogleアカウントでGoogleスプレッドシートを新規作成。
2. メニュー「拡張機能 → Apps Script」でGASを作成し、`Code.gs`を貼り付ける。
3. `CONFIG.SHEET_ID` にスプレッドシートID（URLの `/d/` と `/edit` の間）を入力。
4. GitHubリポジトリを作成し、Pages用の公開URLを確定する。`CONFIG.PUBLIC_SITE_URL` に設定する。
5. GASで `initialize()` を1度実行し、権限を承認。「メール認証」「見学申込」タブが自動作成される。
6. GAS「デプロイ → 新しいデプロイ → ウェブアプリ」。「自分として実行」「アクセスできるユーザー: 全員」。生成された `/exec` URLをコピー。
7. `index.html`の **２か所** の `GAS_WEB_APP_URL_HERE` を、手順6のURLに置換。
8. GitHubリポジトリに `index.html` をアップロードし、`Settings → Pages` を有効にして公開。
9. GitHub Pagesからの送信 → GASの結果画面 → 認証メール → フォーム → 受付QRメール → スプレッドシート保存、まで実機で検証。
10. 検証後、印刷用案内のQRコードは「GitHub Pages申込トップ」のURLを使う。

## 操作の流れ

- 保護者がGitHub Pagesへアクセス → メールアドレスを入力 → GASが専用リンクをメール送信。
- リンクをタップするとGitHub Pagesの申込フォームが開く。リンクの認証トークンは24時間有効で、同じリンクで最大5名分を申し込める。
- １名ごとに申込み → GASがスプレッドシートへ記録 → QRコードをメール内と添付PNGで送信。
- メールそのもの、または添付PNGを印刷すれば、紙で受付QRコードを提示できる。
- 同じメールアドレス・同じ児童生徒氏名・同じ学校の二重申込みは拒否する。
- 「見学申込」シートの `受付状態`／`受付日時`／`アンケート提出` は、当日の受付アプリ／アンケート連携用の列。**今回のコードには当日のQRスキャン受付処理はまだ含まれていない**。

## GitHub とGASの通信

GitHub Pagesは静的サイトです。GAS Webアプリへの一般的なJavaScriptの `fetch` はCORSの制約で結果を読み取れない場合があります。今回は、標準のHTMLフォーム `method=post` でGASに画面遷移し、GAS側が受付結果ページを表示する構成にしました。
つまり、入力フォームの画面はGitHub Pagesですが、送信後の完了表示はGoogle Apps Scriptのページとなります。

## 重要な注意事項

- **絶対に公開GitHubリポジトリに氏名・電話番号・名簿・スプレッドシートの実データを入れないこと。** ただし、GASの `/exec` URLはフォーム送信先として公開される設計。
- `Code.gs` は学校側だけで管理し、GitHubへ公開アップロードしないこと。
- 認証リンクはメールアドレスの**受信権限を確認する仕組み**であり、保護者であること自体を公的に証明するものではない。
- QRはランダムな受付IDのみを含み、氏名や電話番号を含めない。
- QR画像は外部サービス **QuickChart** により生成するため、受付IDだけが外部送信される。学校の情報セキュリティルールで外部QRサービスが認められない場合には、ローカル生成ライブラリへの置換が必要。
- GASの公開フォームにはスパム送信のリスクが残る。現行版には送信頻度制限とハニーポット欄を実装しているが、正式公開前にはTurnstile等のボット対策も推奨。
- `MailApp` のメール送信には日次上限あり。管理アカウントの残件数と申込想定者数を確認すること。
- 公開前に「保護者による申込み」「１児童生徒につき１保護者まで」「緊急時の扱い」「撮影可否」「個人情報の利用目的・削除時期」を最終確認する。
- 保護者の同伴の有無は、当日の参加人数を数えるための追加項目。
- 見学受付人数の上限設定が必要なら `CONFIG.MAX_REGISTRATIONS` に上限数を指定（0は無制限）。
- 専用リンクの秘密を知っていれば第三者もアクセスできるため、メールの転送や共有を避ける旨を案内する。
- GAS側の設定変更後はWebアプリを**新しいバージョンで再デプロイ**すること。
- 受付QRが転送された場合のなりすましは、当日の受付担当による確認と二重読取拒否で対策する。**受付スキャン側の実装は別途必要。**

## 本番投入前のテスト項目

- メール送信成功、迷惑メールでの表示、リンクが開くこと
- 24時間経過したリンクが無効になること
- 同一メールから兄弟姉妹２名申込でそれぞれ異なるQRが届くこと
- 同じ児童生徒の二重申込みが拒否されること
- QR添付画像の印刷とスマホ表示の両方で読み取れること
- 申込情報とスプレッドシートの記録一致、保護者連絡先の妥当性
- QRメール生成サービスの障害時に「送信エラー・要対応」が記録されること
- 当日受付オペレーション、緊急退出、アンケート・解散の手順
